## Overview

AWS provides two firewall mechanisms to control traffic in your VPC:

- **Security Groups (SGs)** — **stateful** firewalls that operate at the resource level (EC2, ENI, RDS, ALB, etc.)
- **Network ACLs (NACLs)** — **stateless** firewalls that operate at the subnet level

Both controls are complementary: traffic must first pass through the subnet's NACL and then through the resource's Security Group.

## Key Concepts

### Stateful vs Stateless

The fundamental difference between Security Groups and NACLs:

| Concept | Stateful (Security Groups) | Stateless (NACLs) |
|---|---|---|
| **What it remembers** | The connection state | Nothing — each packet is independent |
| **Response traffic** | Automatically permitted without a rule | Requires an explicit rule in both directions |
| **Practical example** | Allow HTTP inbound port 80 → response exits automatically | Allow HTTP inbound port 80 → MUST also allow outbound on ephemeral ports |

**Concrete example**:
- A user makes an HTTP request to your EC2 on port 80
- **With SG (stateful)**: the inbound rule for port 80 allows the request. The response exits automatically.
- **With NACL (stateless)**: you need an inbound rule for port 80 (request) AND an outbound rule for ephemeral ports 1024-65535 (response).

### Security Groups in Detail

Security Groups are firewalls for individual resources (EC2, RDS, ALB, ENI, etc.).

#### Security Group Rules

Each rule defines:

| Field | Description | Example |
|---|---|---|
| **IP version** | IPv4 or IPv6 | IPv4 |
| **Type** | Predefined traffic type | HTTP, SSH, Custom TCP |
| **Protocol** | TCP, UDP, ICMP, All | TCP |
| **Port range** | Port or range | 80, 8080-8090 |
| **Source/Destination** | IP, CIDR, or another SG ID | `0.0.0.0/0`, `sg-xxxxxx` |

#### Key Security Group Behavior

- No rules = **everything blocked** (implicit deny)
- Rules can only **allow** traffic — there is no explicit "deny"
- By default, the SG allows **all outbound traffic**
- You can assign **multiple Security Groups** to a resource — rules are **merged** (union of all allows)
- You can use **Security Group IDs as source/destination** — useful for auto-scaling: use the ALB SG as the source in the EC2 SG

#### SG Referencing

Instead of IPs or CIDRs, you can use another SG as source/destination. Example:

| Resource | Inbound Rule |
|---|---|
| EC2 (app tier) | Source: `sg-alb-id`, Port: 8080 |

This allows only instances with the ALB SG to access port 8080 on the EC2, regardless of their IPs. **Ideal for Auto Scaling Groups** where IPs change.

#### Default Security Group

When you create a VPC, a default SG is created:
- **Inbound**: allows all traffic **from the same SG** (self-referencing)
- **Outbound**: allows all traffic to any destination

Modifying the default SG is valid, but best practice is to create custom SGs.

### NACLs in Detail

NACLs filter traffic **entering and leaving a subnet** — they affect all resources in the subnet.

#### NACL Rules

| Field | Description |
|---|---|
| **Rule number** | Determines order (lower = higher priority). Increments of 100 are recommended |
| **Type** | Predefined traffic type |
| **Protocol** | TCP, UDP, ICMP, etc. |
| **Port range** | Port or range |
| **Source/Destination** | CIDR (does not support SG IDs) |
| **Allow / Deny** | Unlike SGs, NACLs can **explicitly deny** |

Rules are processed in **ascending numerical order**. The first matching rule is applied and no further rules are evaluated.

#### Rule * (catch-all)

All NACLs have a `*` rule at the end (implicit rule number) that **denies all** traffic that did not match any previous rule.

#### Default NACL

The NACL automatically created with the VPC (default NACL) **allows all traffic** (inbound and outbound):
- Rule 100: Allow All → everything passes
- Rule *: Deny All → never reached

#### Custom NACL

A new NACL you create manually **denies all** traffic until you add rules:
- Rule *: Deny All → everything blocked until you add rules

### Ephemeral Ports

Ephemeral ports are the source of many issues when configuring NACLs (they do not affect SGs because SGs are stateful).

When a client connects to a server on port 80, the client uses a **random ephemeral port** as its source port to receive the response:

| Operating System | Ephemeral Port Range |
|---|---|
| Linux (modern kernel) | 32768 – 60999 |
| Windows | 49152 – 65535 |
| NAT Gateway | 1024 – 65535 |
| Clients in general | 1024 – 65535 |

**For NACLs**: you must explicitly allow the ephemeral port range in the outbound rules of the server subnet's NACL. If you do not, responses to the client are blocked.

## Comparison: Security Groups vs NACLs

| Feature | Security Groups | NACLs |
|---|---|---|
| **Level** | Resource (EC2, ENI, RDS, ALB) | Subnet |
| **Type** | Stateful | Stateless |
| **Rules** | Allow only | Allow and deny |
| **Rule order** | All evaluated (union) | Numerical order (first match) |
| **Multiple per resource** | Yes (merged) | No (one per subnet) |
| **Default deny** | Implicit (no rules = everything blocked) | Rule `*` at the end |
| **Reference other SGs** | Yes | No (CIDR only) |
| **Ephemeral ports** | Not needed (stateful) | Required in outbound |
| **Explicit block** | No | Yes (can deny specific IPs) |
| **Association** | One or more per resource | Exactly one per subnet |

## Configuration and Troubleshooting

Steps to diagnose connectivity issues in a VPC:

1. **Does the instance have a public IP or EIP?** — Without a public IP there is no internet access
2. **Is there a route to the IGW in the route table?** — Public subnet requires `0.0.0.0/0 → IGW`
3. **Does the Security Group allow the traffic?** — Check inbound rules and the correct port
4. **Does the NACL allow the traffic?** — Check both inbound and outbound (stateless)
5. **Does the NACL allow ephemeral ports in outbound?** — Required for server responses
6. **Are there DENY rules in the NACL that fire before the ALLOW?** — Remember that NACLs process in order

<Callout type="warn">
**SAA-C03 Exam Tips:**
- **Security Groups = Stateful**: if you allow inbound, the outbound response is automatic. **NACLs = Stateless**: you must allow both directions.
- **Order matters in NACLs**: if you have a DENY rule at number 100 and an ALLOW at 200 for the same traffic, the DENY wins (evaluated first).
- **Ephemeral ports are critical in NACLs**: if you block the range 1024-65535 in a NACL outbound rule, you break responses to clients.
- **One subnet = one NACL**. A resource can have **multiple SGs** (they are merged).
- If you need to **block a specific IP**, NACLs are the tool (SGs have no explicit deny).
- The **default NACL allows everything**; a new custom NACL **denies everything** until you add rules.
</Callout>
