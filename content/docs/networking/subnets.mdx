## Resumen

Las **subnets** (subredes) son segmentos de IP dentro de tu VPC donde despliegas recursos. Cada subnet reside en **una sola zona de disponibilidad (AZ)**, lo que determina en qué AZ queda el recurso desplegado. Una subnet no puede abarcar múltiples AZs.

La diferencia fundamental entre una subnet pública y una privada es la presencia de una **ruta hacia un Internet Gateway** en su route table — no simplemente la asignación de IP pública.

## Conceptos Clave

### Direcciones IP Reservadas

En cada subnet, **5 direcciones IP están reservadas** por AWS y no pueden asignarse a recursos. Para una subnet `10.0.1.0/24`:

| Dirección | IP Ejemplo | Propósito | Por qué está reservada |
|---|---|---|---|
| Primera (`.0`) | 10.0.1.0 | Dirección de red | Identifica la red, no puede asignarse a hosts |
| Segunda (`.1`) | 10.0.1.1 | Router de la VPC | El VPC router usa esta IP para enrutar tráfico entre subnets |
| Tercera (`.2`) | 10.0.1.2 | Servidor DNS de AWS | Reservada para el resolver DNS de Amazon (169.254.169.253) |
| Cuarta (`.3`) | 10.0.1.3 | Reservada por AWS | Para uso futuro de servicios de AWS |
| Última (`.255`) | 10.0.1.255 | Dirección de broadcast | Broadcast de red (aunque AWS no soporta broadcast, la reserva) |

**Implicación práctica:** si necesitas exactamente 29 IPs para hosts, necesitas una subnet /27 (32 IPs totales, 27 utilizables), no una /28 (16 IPs totales, 11 utilizables).

### CIDR Sizing

| Prefijo | IPs Totales | IPs Utilizables | Uso Típico |
|---|---|---|---|
| /16 | 65,536 | 65,531 | VPC completa |
| /20 | 4,096 | 4,091 | Subnet grande (default VPC) |
| /22 | 1,024 | 1,019 | Subnet mediana-grande |
| /24 | 256 | 251 | Subnet estándar más común |
| /25 | 128 | 123 | Subnet mediana |
| /26 | 64 | 59 | Subnet pequeña |
| /27 | 32 | 27 | Subnet muy pequeña |
| /28 | 16 | 11 | Subnet mínima permitida |

### Subnets Públicas vs Privadas

Lo que determina si una subnet es pública o privada es **la ruta en su route table**, no el nombre ni ningún flag especial:

| Característica | Subnet Pública | Subnet Privada |
|---|---|---|
| **Ruta por defecto** | `0.0.0.0/0` → Internet Gateway | Sin ruta a IGW (o ruta a NAT GW) |
| **Acceso desde internet** | Sí (requiere IP pública o EIP) | No (internet no puede iniciar conexiones) |
| **Acceso a internet** | Directo vía IGW | Solo saliente vía NAT Gateway |
| **Recursos típicos** | Load balancers, bastion hosts, NAT GW | EC2 de aplicación, bases de datos, caches |
| **Auto-assign IP pública** | Generalmente habilitado | Generalmente deshabilitado |

### Auto-assign Public IP

La opción **Auto-assign public IPv4 address** en una subnet determina si las instancias lanzadas en ella reciben automáticamente una IP pública:

- Solo tiene efecto en subnets con ruta al IGW (subnets públicas)
- La IP pública asignada automáticamente **no es una Elastic IP** — cambia al detener/iniciar la instancia
- Para IPs estáticas necesitas una **Elastic IP**
- Puedes sobrescribir el setting de la subnet al lanzar una instancia específica

### IPv6 en Subnets

- Cada subnet puede recibir un bloque IPv6 **/64** (del /56 asignado a la VPC)
- Las IPs IPv6 son **globalmente únicas** y públicamente enrutables por diseño
- No existe NAT para IPv6 — usa **Egress-Only Internet Gateway** para tráfico saliente IPv6 desde subnets privadas
- Una subnet puede ser **dual-stack** (IPv4 + IPv6) o **solo IPv6**
- Las IPs IPv6 persisten mientras la instancia existe (no cambian al reiniciar)

## Casos de Uso

| Tier | Tipo de Subnet | Recurso Típico | Razón |
|---|---|---|---|
| Web / Presentación | Pública | ALB, CloudFront Origin, Bastion Host | Necesita ser accesible desde internet |
| Aplicación | Privada | EC2 con lógica de negocio, ECS Tasks | Solo accesible desde el ALB, no desde internet |
| Base de datos | Privada | RDS, ElastiCache, DynamoDB VPC Endpoint | Solo accesible desde la capa de aplicación |
| NAT | Pública | NAT Gateway | Necesita IP pública para reenviar tráfico saliente |
| VPN / Direct Connect | Privada | Virtual Private Gateway | Conectividad híbrida, no expuesta a internet |
| Administración | Pública (restringida) | Bastion Host / Session Manager | Acceso administrativo controlado |

## Configuración

Para crear una subnet desde la consola AWS:

1. Navega a **VPC → Subnets → Create subnet**
2. Selecciona la **VPC** destino
3. Asigna un **nombre descriptivo** (ej: `prod-public-1a`, `prod-private-1a`)
4. Selecciona la **Availability Zone** (nunca uses "No preference" en producción)
5. Define el **bloque CIDR IPv4** dentro del rango de la VPC (ej: `10.0.1.0/24`)
6. Opcionalmente asigna un **bloque CIDR IPv6 /64**
7. Haz clic en **Create subnet**

Después de crear la subnet:
- Para hacerla **pública**: edita su route table y agrega una ruta `0.0.0.0/0 → IGW`; habilita auto-assign public IP
- Para hacerla **privada con acceso a internet**: configura route table con `0.0.0.0/0 → NAT Gateway`

<Callout type="warn">
**Consejos para el examen SAA-C03:**
- Las subnets **no pueden solaparse** dentro de la misma VPC.
- Siempre hay **5 IPs reservadas** por AWS en cada subnet (no 4, no 3 — siempre 5).
- Las subnets residen en **una sola AZ**. Para alta disponibilidad, despliega recursos en subnets de múltiples AZs.
- Lo que hace pública a una subnet es una **ruta hacia el IGW** en su route table, no un flag en la subnet misma.
- La IP pública auto-asignada **no es una Elastic IP** y cambia al detener/iniciar la instancia.
- Para outbound IPv6 desde subnets privadas, usa **Egress-Only Internet Gateway**, no NAT Gateway.
</Callout>
