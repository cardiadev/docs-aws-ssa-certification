## Overview

A **NAT Gateway** allows resources in private subnets to access the internet for downloading updates and security patches, **without allowing the internet to initiate connections to those resources**. The connection must be initiated from within the VPC.

## The Problem it Solves

If you have a server in a private subnet that needs internet access (e.g. to download updates), you could move it to a public subnet — but that would expose it to the entire internet.

**NAT Gateway** solves this problem: it allows **outbound** connections (from the VPC to the internet) but **blocks inbound** connections (from the internet to the VPC).

## How it Works

The NAT Gateway requires a previously configured **Internet Gateway**. The flow is:

1. Create an **Internet Gateway** and attach it to the VPC
2. Create a **public subnet** with a default route to the IGW
3. Deploy the **NAT Gateway** into the public subnet
4. Configure the private subnet's route table with a default route (`0.0.0.0/0`) pointing to the NAT Gateway

The traffic flow:

```
Server (private subnet) → NAT Gateway (public subnet) → Internet Gateway → Internet
```

The server has no public IP, so the internet can never initiate a direct connection to it.

## Key Features

| Feature | Detail |
|---|---|
| **Managed service** | AWS manages it completely after deployment |
| **Location** | Deployed in a **public subnet** |
| **Resilience** | Specific to an **AZ** (not region-resilient) |
| **Elastic IP** | Requires an associated Elastic IP |
| **Bandwidth** | 5 Gbps by default, auto-scales up to 100 Gbps |
| **Billing** | Charged per hour of operation + per GB of data processed |

## High Availability

Unlike Internet Gateways, NAT Gateways are **not region-resilient**. If the AZ where your NAT Gateway lives goes down, you lose internet access for the private subnets that use it.

For redundancy, deploy **one NAT Gateway per AZ** you use and configure each private subnet's route table to point to the NAT Gateway in its own AZ.

<Callout type="warn">
**For the SAA-C03 exam:** NAT Gateways need an Internet Gateway to work. They are AZ-specific, so you need one per AZ for high availability. They use Elastic IPs. Billing is per hour + per GB processed. They allow outbound traffic but block inbound connections from the internet.
</Callout>
