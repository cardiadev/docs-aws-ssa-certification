## Overview

Amazon CloudFront is a fully managed global **Content Delivery Network (CDN)** from AWS. With more than **400 edge locations** worldwide, it delivers static, dynamic, and streaming content with low latency by caching it close to end users.

CloudFront integrates natively with S3, ALB, EC2, and custom HTTP origins. It includes DDoS protection through **AWS Shield Standard** at no additional cost.

## Key Concepts

### Origins

CloudFront supports the following origin types:

| Origin Type | Description |
|---|---|
| **Amazon S3** | Static websites, files, assets |
| **Application Load Balancer** | Dynamic web applications |
| **EC2 Instance** | Custom application servers |
| **Custom HTTP Origin** | Any publicly accessible HTTP/HTTPS server |
| **S3 Static Website** | Bucket configured as a static website |

### OAC vs OAI

To restrict direct S3 access and force users through CloudFront:

| Feature | OAC (Origin Access Control) | OAI (Origin Access Identity) |
|---|---|---|
| **Status** | Recommended (new) | Legacy |
| **S3 SSE-KMS** | Supported | Not supported |
| **HTTP Methods** | All (GET, PUT, DELETE, etc.) | GET, HEAD, OPTIONS |
| **S3 Regions** | All | Limited |

> **Recommendation:** Always use **OAC** for new distributions. OAI is considered deprecated.

### Behaviors and Cache Key

- **Behaviors** define rules based on path patterns (e.g., `/api/*` → ALB, `/*.jpg` → S3).
- The **Cache Key** determines what makes an object unique in cache. It can include: query strings, headers, and cookies.
- **Cache Policies** and **Origin Request Policies** control what is included in the key and what is forwarded to the origin.

### Signed URLs vs Signed Cookies

| Feature | Signed URL | Signed Cookie |
|---|---|---|
| **Scope** | A single file | Multiple files or entire site |
| **Use case** | Download a specific file | Premium content / subscriptions |
| **Compatibility** | All clients | Browsers only |
| **Expiration** | Configurable per URL | Configurable per cookie |

### Geo-Restriction

- **Allowlist:** Only allows access from specific countries.
- **Blocklist:** Blocks access from specific countries.
- Applied at the distribution level, not per individual behavior.

### Price Classes

| Class | Included Edge Locations | Cost |
|---|---|---|
| **Price Class All** | All edge locations (global) | Highest |
| **Price Class 200** | Excludes most expensive regions | Medium |
| **Price Class 100** | Only cheapest regions | Lowest |

### WAF Integration

- You can attach an **AWS WAF Web ACL** to a CloudFront distribution.
- Allows blocking IPs, countries, and malicious request patterns.
- Provides protection against DDoS attacks (Layer 7).
- **Important:** WAF for CloudFront must be created in the **us-east-1 (N. Virginia)** region.

### Lambda@Edge and CloudFront Functions

| Feature | CloudFront Functions | Lambda@Edge |
|---|---|---|
| **Max execution time** | < 1 ms | Up to 30 s (origin triggers) |
| **Max memory** | 2 MB | Up to 10,240 MB |
| **Cost** | Very low | Higher |
| **Use cases** | Rewrites, redirects, simple headers | Auth, A/B testing, complex logic |
| **Network access** | No | Yes |
| **Trigger points** | Viewer Request / Viewer Response | All 4 triggers |

## Distribution Types and Protocols

CloudFront supports the following origin and viewer protocols:

| Setting | Options |
|---|---|
| **Viewer Protocol Policy** | HTTP only, HTTPS only, Redirect HTTP to HTTPS |
| **Origin Protocol Policy** | HTTP only, HTTPS only, Match viewer |
| **HTTP versions** | HTTP/1.1, HTTP/2, HTTP/3 |
| **Allowed HTTP Methods** | GET/HEAD, GET/HEAD/OPTIONS, All methods (including PUT/POST/PATCH/DELETE) |

### TTL and Cache Control

CloudFront TTL can be controlled through:

- **Cache-Control: max-age=X** — the origin tells the edge location the TTL.
- **Expires header** — absolute expiration date.
- **CloudFront minimum/maximum/default TTL** — limits configured in the behavior.

| Origin header | Effect on CloudFront |
|---|---|
| `Cache-Control: max-age=3600` | CloudFront caches for 1 hour |
| `Cache-Control: no-cache` | CloudFront validates with origin on every request |
| `Cache-Control: no-store` | CloudFront does not cache |
| No cache header | CloudFront uses Default TTL (86,400 s) |

## Comparison: CloudFront vs S3 Transfer Acceleration

| Feature | CloudFront | S3 Transfer Acceleration |
|---|---|---|
| **Purpose** | Global content distribution (reads) | Accelerate uploads to S3 |
| **Traffic direction** | Origin → Users (download) | Users → S3 (upload) |
| **Caching** | Yes | No |
| **Edge Locations** | 400+ | Same edge network |
| **Use case** | CDN, websites, streaming | Global S3 uploads |

## Use Cases

| Scenario | CloudFront Solution |
|---|---|
| Global static website | S3 + CloudFront + OAC |
| Low-latency global API | ALB + CloudFront with low TTL |
| Video streaming | CloudFront + S3 (HLS/DASH) |
| Content protection | Signed URLs / Signed Cookies |
| Country-level blocking | Geo-Restriction (blocklist) |
| DDoS protection | WAF + Shield Standard |
| Edge customization | Lambda@Edge / CloudFront Functions |

## Configuration

Typical steps to create a CloudFront distribution with an S3 origin:

1. Create an S3 bucket (without public access enabled).
2. Create a CloudFront distribution → S3 origin.
3. Create and associate an **Origin Access Control (OAC)**.
4. Update the **S3 bucket policy** to allow access only from CloudFront.
5. Configure behaviors (path patterns, HTTP methods, TTL).
6. (Optional) Attach a **WAF Web ACL** (created in us-east-1).
7. (Optional) Configure a custom domain with an ACM certificate in **us-east-1**.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "Service": "cloudfront.amazonaws.com" },
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::my-bucket/*",
    "Condition": {
      "StringEquals": {
        "AWS:SourceArn": "arn:aws:cloudfront::123456789012:distribution/EDFDVBD6EXAMPLE"
      }
    }
  }]
}
```

<Callout type="warn">
**Exam Tips — SAA-C03:**
- **OAC replaces OAI:** For new distributions always use OAC. OAI is legacy. OAC supports SSE-KMS on S3.
- **Signed URLs for a single file; Signed Cookies for multiple files** or entire site access.
- **CloudFront can cache dynamic content** if Cache Policies are configured properly (low TTL).
- **WAF for CloudFront MUST be created in us-east-1** (N. Virginia), even if resources are in another region.
- **SSL/TLS certificate for custom domain** must also be in ACM us-east-1.
- **Price Class 100** = only cheapest regions; does not cover all global audiences.
- **Geo-restriction** operates at the distribution level, not per individual behavior.
- **CloudFront Functions** run only on Viewer Request/Response and are faster and cheaper.
- **Default TTL:** 86,400 seconds (24 hours). Can be overridden with Cache-Control headers.
- **Invalidations:** Charged after the first 1,000 paths per month.
</Callout>
