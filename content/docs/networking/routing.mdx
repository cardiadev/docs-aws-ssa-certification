## Resumen

Cada VPC tiene un **VPC router** que enruta el tráfico entre subnets y hacia y desde la VPC. El router tiene una interfaz en cada subnet, accesible desde la dirección **network + 1** (ej: si la subnet es `10.0.1.0/24`, el router está en `10.0.1.1`).

El enrutamiento se controla mediante **route tables**: conjuntos de reglas (rutas) que el router consulta para determinar a dónde enviar cada paquete. Cada ruta tiene una **Destination** (destino CIDR) y un **Target** (próximo salto).

## Conceptos Clave

### Longest Prefix Match

Cuando un paquete coincide con más de una ruta, el router selecciona la **ruta más específica** (prefijo más largo). Este es el principio fundamental del enrutamiento IP.

**Ejemplo concreto:**

| Destination | Target | Coincide con |
|---|---|---|
| `10.0.0.0/16` | local | Todos los paquetes a 10.0.x.x |
| `10.0.1.0/24` | tgw-xxxx | Paquetes a 10.0.1.x |

Si un paquete va a `10.0.1.5`:
- Coincide con `10.0.0.0/16` (prefijo /16)
- Coincide con `10.0.1.0/24` (prefijo /24)
- **Gana `10.0.1.0/24`** porque /24 es más específico que /16

Si un paquete va a `10.0.2.5`:
- Solo coincide con `10.0.0.0/16`
- Se usa la ruta `local`

### Ruta Local (Local Route)

Todas las route tables tienen **al menos una ruta local** que no se puede eliminar ni modificar:

| Destination | Target |
|---|---|
| `10.0.0.0/16` (CIDR de la VPC) | `local` |

Esta ruta permite que cualquier recurso dentro de la VPC pueda comunicarse con cualquier otro recurso en la misma VPC sin salir a internet. Si la VPC tiene IPv6, también existirá una ruta local para el bloque CIDR IPv6.

**La ruta local no se puede eliminar.** Es la base de la comunicación intra-VPC.

### Route Tables: Principal vs Personalizada

| Tipo | Descripción |
|---|---|
| **Main (principal)** | Creada automáticamente con la VPC. Las nuevas subnets se asocian a ella por defecto |
| **Custom (personalizada)** | Creada manualmente. Debes asociarla explícitamente a las subnets que la usarán |

Cada subnet está asociada a **exactamente una** route table. Múltiples subnets pueden compartir la **misma** route table.

**Mejor práctica:** no agregues rutas hacia internet a la main route table. Crea route tables personalizadas para subnets públicas y privadas.

### Tipos de Rutas

| Tipo | Descripción | Ejemplo |
|---|---|---|
| **Estática** | Agregada manualmente por el administrador | `0.0.0.0/0 → igw-xxxx` |
| **Propagada** | Aprendida dinámicamente vía BGP (VPN/Direct Connect) | `192.168.1.0/24` (red on-premises) |
| **Local** | Siempre presente, no modificable | `10.0.0.0/16 → local` |

Las rutas propagadas se habilitan activando **route propagation** en la route table cuando hay un Virtual Private Gateway (VGW) adjunto.

### Múltiples Route Tables: Ejemplo Multi-Tier

Un patrón común para arquitecturas de 3 capas:

| Route Table | Subnets Asociadas | Rutas Clave |
|---|---|---|
| `rtb-public` | Subnets públicas (web tier) | `0.0.0.0/0 → IGW`, `10.0.0.0/16 → local` |
| `rtb-private-app` | Subnets privadas (app tier) | `0.0.0.0/0 → NAT GW`, `10.0.0.0/16 → local` |
| `rtb-private-db` | Subnets privadas (db tier) | Solo `10.0.0.0/16 → local` (sin acceso a internet) |

Las subnets de base de datos solo tienen la ruta local — no pueden acceder a internet ni ser accedidas desde él.

## Configuración

Para agregar rutas a una route table:

1. Navega a **VPC → Route Tables**
2. Selecciona la route table que quieres modificar
3. Haz clic en la pestaña **Routes → Edit routes**
4. Haz clic en **Add route**
5. Define la **Destination** (ej: `0.0.0.0/0`)
6. Selecciona el **Target** (IGW, NAT Gateway, VGW, TGW, VPC Peering, etc.)
7. Haz clic en **Save changes**

Para asociar una subnet:
1. Selecciona la route table
2. Ve a **Subnet associations → Edit subnet associations**
3. Marca las subnets que deben usar esta route table
4. Guarda los cambios

<Callout type="warn">
**Consejos para el examen SAA-C03:**
- **Longest prefix match**: cuando hay rutas solapadas, siempre gana el prefijo más largo (más específico). Una ruta `10.0.1.0/24` siempre tiene prioridad sobre `10.0.0.0/16` para paquetes a `10.0.1.x`.
- **La ruta local no se puede eliminar** ni modificar. Siempre permite comunicación dentro de la VPC.
- **Una subnet = una route table**. Una route table puede tener múltiples subnets.
- Las nuevas subnets se asocian automáticamente a la **main route table** si no las asocias a otra.
- Para VPN/Direct Connect, habilita **route propagation** para que las rutas BGP se agreguen automáticamente.
- Las route tables de subnets de base de datos **no deben tener ruta a internet** por seguridad.
</Callout>

<Callout type="info">
**Cheat Sheet — Route Tables:**

| Propiedad | Valor |
|---|---|
| Ruta local | Siempre presente, no eliminable |
| Ruta local CIDR | CIDR de la VPC (ej: 10.0.0.0/16) |
| Subnet ↔ Route Table | 1 subnet = 1 route table |
| Route Table ↔ Subnets | 1 route table = N subnets |
| Subnet nueva → asociada a | Main route table (por defecto) |
| Tipos de rutas | Estática, propagada (BGP), local |
| Selección de ruta | Longest prefix match |
| Rutas propagadas | Requiere VGW + route propagation habilitado |
| Max route tables por VPC | 200 (ajustable) |
| Max rutas por route table | 1,000 (ajustable) |
</Callout>
