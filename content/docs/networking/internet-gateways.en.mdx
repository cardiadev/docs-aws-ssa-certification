## Overview

An **Internet Gateway (IGW)** is the component that allows resources within a VPC to communicate with the internet. It acts as the entry and exit point between the VPC and the public internet. Without an IGW, all resources in a VPC are private with no internet access.

Fundamental characteristics:
- Attached to a **VPC** (not a subnet) and is **region-resilient** (covers all AZs in the region)
- A VPC can have **at most one** Internet Gateway
- An Internet Gateway can only be attached to **one VPC** at a time
- It is a **fully managed** and **highly available** service from AWS — it is not a bottleneck
- No bandwidth limit — scales horizontally

## Key Concepts

### NAT in the IGW

The Internet Gateway performs **Network Address Translation (NAT)** for instances with public IPs:

- **Outbound traffic**: the IGW replaces the private source IP (`10.0.0.5`) with the associated public IP (`54.12.34.56`)
- **Inbound traffic**: the IGW replaces the public destination IP (`54.12.34.56`) with the corresponding private IP (`10.0.0.5`)

**Important**: the EC2 instance **does not know it has a public IP**. The operating system only sees the private IP. The IGW performs NAT transparently. You can verify this: inside an EC2, `ifconfig` only shows the private IP.

For **Elastic IPs** (static IPs), the same mechanism applies: the IGW maps the EIP to the instance's private IP.

### Requirements for Internet Access

For an EC2 instance to have internet access, **4 requirements** must be met:

| # | Requirement | Description |
|---|---|---|
| 1 | **Public IP or Elastic IP** | The instance must have an associated public IP |
| 2 | **Route to the IGW** | The subnet's route table must have `0.0.0.0/0 → IGW` |
| 3 | **Security Group allows** | The SG must permit outbound traffic (and inbound if applicable) |
| 4 | **NACL allows** | The NACL must permit both inbound and outbound traffic (including ephemeral ports) |

If any of these 4 is missing, the instance will not have internet access.

### Egress-Only Internet Gateway

The **Egress-Only Internet Gateway** is a variant of the IGW designed exclusively for **outbound IPv6 traffic**:

| Feature | Internet Gateway | Egress-Only IGW |
|---|---|---|
| **Protocol** | IPv4 and IPv6 | IPv6 only |
| **Direction** | Bidirectional | Outbound only (egress) |
| **Inbound connections** | Allowed (if public IP exists) | Blocked |
| **Stateful** | Yes | Yes |
| **Purpose** | Full internet access | NAT for private IPv6 |

Because IPv6 addresses are publicly routable, you need the Egress-Only IGW to give outbound internet access to instances with IPv6 **without allowing** the internet to initiate connections to them (similar to the role a NAT Gateway plays for IPv4).

## Comparison: IGW vs Egress-Only IGW

| Property | Internet Gateway | Egress-Only IGW |
|---|---|---|
| **Protocol** | IPv4 + IPv6 | IPv6 only |
| **Traffic direction** | Bidirectional | Outbound only |
| **Inbound traffic** | Yes (requires public IP) | No |
| **Stateful** | Yes | Yes |
| **VPCs per IGW** | 1 | 1 |
| **IGWs per VPC** | 1 | 1 |
| **Use case** | Public subnets with IPv4/IPv6 | Private subnets with IPv6 |
| **IPv4 equivalent** | N/A | NAT Gateway |

## Configuration

To make a subnet public using the IGW:

1. **Create the Internet Gateway**:
   - Navigate to **VPC → Internet Gateways → Create internet gateway**
   - Assign a name and click **Create**

2. **Attach the IGW to the VPC**:
   - Select the newly created IGW
   - Click **Actions → Attach to VPC**
   - Select your VPC and confirm

3. **Configure the route table**:
   - Create or edit a custom route table for the public subnet
   - Add the route: `Destination: 0.0.0.0/0` → `Target: igw-xxxxxxxx`
   - For IPv6: add `Destination: ::/0` → `Target: igw-xxxxxxxx`

4. **Associate the subnet**:
   - Associate the public subnet with the route table that has the IGW route

5. **Enable auto-assign public IP** (optional):
   - In the public subnet, edit the settings and enable **Auto-assign public IPv4 address**

For the **Egress-Only IGW** (IPv6):
- Create the Egress-Only IGW from **VPC → Egress-Only Internet Gateways**
- Add the IPv6 route to the private subnet's route table: `::/0 → eigw-xxxxxxxx`

<Callout type="warn">
**SAA-C03 Exam Tips:**
- The IGW is **region-resilient** — you do not need one per AZ; one per VPC is sufficient.
- A VPC can have **only one IGW** attached at a time. There is no way to add a second.
- For an instance to access the internet you need all **4 requirements**: public IP, route to IGW, SG allows, NACL allows.
- The IGW performs NAT **transparently** — the EC2 instance only sees its private IP.
- For outbound IPv6 from private subnets, use the **Egress-Only IGW**, not the NAT Gateway (NAT GW does not handle IPv6).
- The IGW is a managed service — **it has no bandwidth bottleneck**.
</Callout>
