## Overview

**Amazon Route 53** is AWS's fully managed DNS service. It provides domain registration, DNS record management, health checks, and multiple routing policies to control how traffic is directed to AWS and external resources.

It is a **global service** (not regional) with high availability and scalability, operating with a 100% SLA.

## Key Concepts

### Alias vs CNAME

| Feature | Alias | CNAME |
|---|---|---|
| **Zone apex (root domain)** | Yes (`example.com`) | No (subdomains only) |
| **AWS resources** | Yes (native) | No (any hostname) |
| **Query charge** | No additional charge | Standard charge |
| **Valid targets** | AWS resources only | Any hostname |
| **TTL** | Managed by AWS | Manually configurable |
| **Health checks** | Yes (for some targets) | Yes |

> **Key rule:** Use **Alias** to point to AWS resources (ELB, CloudFront, S3, API Gateway). Use **CNAME** for external hostnames. **Only Alias can be used at the zone apex** (root domain).

### 7 Routing Policies

| Policy | Use Case | Health Checks |
|---|---|---|
| **Simple** | A single target resource | No |
| **Weighted** | A/B testing, gradual migration | Yes |
| **Latency** | Route to lowest-latency resource | Yes |
| **Failover** | Active-passive DR | Required |
| **Geolocation** | Content by country or continent | Yes |
| **Geoproximity** | Route by geographic proximity + bias | Yes (requires Traffic Flow) |
| **Multivalue** | Multiple healthy IPs (not a replacement for ELB) | Yes |

#### Simple
- Returns a static DNS record.
- If multiple values, returns all and the client chooses randomly.
- **Does not support health checks.**

#### Weighted
- Assigns weights to each record (0-255).
- `Weight 0` = no traffic sent to that resource.
- Useful for **A/B testing** and gradual migrations.

#### Latency
- Routes to the resource with the **lowest network latency** from the user's perspective.
- Requires records in multiple regions.

#### Failover
- **Active-Passive** configuration: primary (active) and secondary (passive).
- **Requires a health check** on the primary resource.
- If the primary fails, Route 53 automatically routes to the secondary.

#### Geolocation
- Routes based on the **geographic location** of the user (country, continent, or default).
- Different from Latency: does not measure latency, only location.
- Useful for legal restrictions, language, or regional customization.

#### Geoproximity
- Routes based on geographic location with the ability to adjust the **bias**.
- `Positive bias` = expand the coverage area of a resource.
- `Negative bias` = reduce the coverage area.
- **Requires Route 53 Traffic Flow** (visual policy editor).

#### Multivalue
- Returns up to **8 healthy records** per query.
- Not a substitute for a load balancer (no advanced routing).
- Each record can have an associated health check.

### Health Checks

| Type | Description |
|---|---|
| **Endpoint** | Monitors an HTTP/HTTPS/TCP endpoint |
| **Calculated** | Combines results from multiple health checks (AND/OR) |
| **CloudWatch Alarm** | Passes/fails based on a CloudWatch alarm state |

- Route 53 health checks run from multiple global locations.
- An endpoint is considered healthy if **>18%** of health checkers see it as healthy.
- **Private endpoints** can be monitored using CloudWatch Alarm-based health checks.

### Private Hosted Zones

- A **Private Hosted Zone** is only accessible from **associated VPCs**.
- DNS traffic does not leave the private network.
- Supports **split-horizon DNS**: same domain with different responses depending on whether the query comes from a private VPC or the public internet.

### DNSSEC

- **DNSSEC** adds cryptographic signatures to DNS records to prevent cache poisoning attacks.
- Route 53 supports DNSSEC for public hosted zones.

### Resolver Endpoints

| Type | Direction | Use Case |
|---|---|---|
| **Inbound** | On-premises → Route 53 | Resolve AWS DNS from corporate network |
| **Outbound** | Route 53 → On-premises DNS | Resolve corporate DNS from AWS (hybrid DNS) |

## DNS Record Types

Route 53 supports all standard DNS record types:

| Type | Description | Example |
|---|---|---|
| **A** | Maps a hostname to an IPv4 address | `app.example.com → 1.2.3.4` |
| **AAAA** | Maps a hostname to an IPv6 address | `app.example.com → 2001:db8::1` |
| **CNAME** | Maps a hostname to another hostname | `www.example.com → app.example.com` |
| **Alias** | Maps to AWS resources (Route 53 extension) | `example.com → xyz.elb.amazonaws.com` |
| **MX** | Mail exchange records | Mail server |
| **TXT** | Text records | Domain verification, SPF |
| **NS** | Name server records | Zone delegation |
| **SOA** | Start of Authority | Zone information |

## Hosted Zones

### Public Hosted Zone

- Resolves DNS queries from the **public internet**.
- Used for publicly accessible domains.
- AWS charges per hosted zone and per DNS query.

### Private Hosted Zone

- Resolves queries only from **associated VPCs**.
- Multiple VPCs can be associated with the same private hosted zone (even across accounts using Resource Access Manager).
- Requires VPC options `enableDnsHostnames` and `enableDnsSupport` to be enabled.

## Use Cases by Policy

| Scenario | Recommended Policy |
|---|---|
| Simple website, one server | Simple |
| Gradually deploy new version | Weighted |
| Global users, lowest possible latency | Latency |
| Active-passive disaster recovery | Failover |
| Different content by country/language | Geolocation |
| Expand/reduce regional coverage area | Geoproximity |
| DNS responses with multiple healthy IPs | Multivalue |

## Configuration

Steps to create a Failover policy:

1. Create a **Hosted Zone** for the domain.
2. Create a **Health Check** for the primary resource.
3. Create a DNS record with **Failover** policy → type **Primary**, associate the health check.
4. Create another DNS record with **Failover** policy → type **Secondary** (no health check required).
5. Route 53 will automatically route to the secondary if the primary fails.

<Callout type="warn">
**Exam Tips — SAA-C03:**
- **Alias at zone apex** (root domain like `example.com`): only Alias works, not CNAME.
- **Geoproximity requires Traffic Flow** to configure the visual bias.
- **Failover requires health checks** on the primary resource.
- **Weighted with value 0** = no traffic sent to that resource.
- **Multivalue is NOT a load balancer** — it simply returns multiple healthy IPs.
- **Latency vs Geolocation:** Latency routes to lowest latency; Geolocation routes by geographic location.
- **Private Hosted Zones** require association with a VPC.
- **Health checks for private endpoints** require CloudWatch Alarm-based health checks.
- **Split-horizon DNS:** same zone, different responses for VPC vs internet.
- Route 53 is a **global service** — it is not in any specific region.
</Callout>
