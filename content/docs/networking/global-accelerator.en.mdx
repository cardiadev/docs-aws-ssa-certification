## Overview

**AWS Global Accelerator** is a network acceleration service that improves the availability and performance of applications using the **AWS global backbone network**. It provides **2 static Anycast IP addresses** that serve as a fixed entry point for global users.

Unlike CloudFront, Global Accelerator **does not cache content**. Instead, it routes network traffic (TCP/UDP) from users to the nearest healthy endpoint using the AWS private network instead of the public internet.

## Key Concepts

### 2 Static Anycast IPs

- Global Accelerator always provides **exactly 2 static IPs**.
- They are **Anycast**: multiple locations advertise the same IP; traffic is automatically routed to the nearest node.
- These IPs **do not change** even if you change the underlying endpoints.
- Ideal when users need fixed IPs for whitelisting in corporate firewalls.

### Endpoint Types

| Endpoint Type | Description |
|---|---|
| **Application Load Balancer** | Public or private ALB |
| **Network Load Balancer** | Public or private NLB |
| **EC2 Instance** | Instance with a public IP |
| **Elastic IP** | EIP associated with a resource |

Endpoints can be in **multiple AWS regions**, and Global Accelerator routes to the healthiest and lowest-latency endpoint.

### Traffic Dials

- Each **Endpoint Group** has a **traffic dial** from 0% to 100%.
- Allows controlling what percentage of traffic is sent to an endpoint group.
- Useful for **blue/green deployments** and gradual migrations between regions.

```
Endpoint Group us-east-1: traffic dial = 80%
Endpoint Group eu-west-1: traffic dial = 20%
```

### Endpoint Weights

- Within an Endpoint Group, each endpoint can have a **weight** from 0 to 255.
- Traffic is distributed proportionally based on weights.
- Useful for weighted distribution within the same region.

### Acceleration vs CloudFront

| Feature | Global Accelerator | CloudFront |
|---|---|---|
| **Type** | Network acceleration | CDN / cache |
| **Layer** | Layer 3/4 (TCP/UDP) | Layer 7 (HTTP/HTTPS) |
| **Caching** | No | Yes |
| **Static IPs** | Yes (2 Anycast IPs) | No (dynamic domain) |
| **Protocols** | TCP and UDP | HTTP, HTTPS, WebSocket |
| **Latency improvement** | Network connection | Content delivery |

### Accelerated VPN

- Global Accelerator can be used to **accelerate AWS Site-to-Site VPN connections**.
- VPN traffic uses the AWS backbone instead of the public internet from the nearest edge location.

### Health Checks

- Global Accelerator performs **continuous health checks** on endpoints.
- If an endpoint fails, traffic is automatically redirected to the next healthiest endpoint.
- **Failover occurs in less than 30 seconds**.

## How Anycast Works

**Anycast** routing is the core technology of Global Accelerator:

1. The 2 static IPs are **announced from multiple edge locations** simultaneously via BGP.
2. When a user makes a request, internet routing protocols direct it to the **nearest edge location** announcing that IP.
3. From the edge location, traffic enters the **AWS private network (backbone)**.
4. AWS internally routes to the healthiest and lowest-latency endpoint.

```
User (Tokyo)  ─→ Tokyo edge location (AWS backbone) ─→ ALB us-east-1
User (London) ─→ London edge location (AWS backbone) ─→ ALB us-east-1
```

Both users use the **same 2 IPs** but their traffic enters the backbone from the nearest point.

## Accelerator Structure

A Global Accelerator has the following hierarchy:

```
Accelerator
├── 2 Static Anycast IPs
└── Listener (TCP/UDP, port(s))
    ├── Endpoint Group — us-east-1 Region (traffic dial: 80%)
    │   ├── ALB us-east-1 (weight: 128)
    │   └── ALB us-east-1 backup (weight: 128)
    └── Endpoint Group — eu-west-1 Region (traffic dial: 20%)
        └── NLB eu-west-1 (weight: 255)
```

### Listeners

- Define the **protocol** (TCP or UDP) and **port** range that Global Accelerator accepts.
- Support **multiple ports** in a single listener (e.g., 80, 443, 8080).
- Traffic from the listener is distributed across Endpoint Groups based on traffic dials.

### Endpoint Groups

- Each Endpoint Group is associated with an **AWS region**.
- Contains one or more endpoints within that region.
- The **traffic dial** controls what percentage of listener traffic is sent to that group (0-100%).
- Useful for **canary deployments**: sending 5% of traffic to a new region before full rollout.

## Costs

| Component | Cost |
|---|---|
| **Fixed fee per accelerator** | Per hour while the accelerator is active |
| **Premium data transfer** | Per GB transferred through the backbone (premium surcharge on top of standard transfer cost) |
| **Data from internet to accelerator** | No additional charge |

> Global Accelerator has a **fixed hourly fee** plus a "premium" data transfer fee reflecting use of the AWS backbone. It is more expensive than direct routing but provides better performance and availability.

## Configuration

Steps to create a Global Accelerator:

1. In the AWS console, go to **Global Accelerator → Create accelerator**.
2. Assign a name; 2 static Anycast IPs are automatically generated.
3. Configure **Listeners** (protocol: TCP or UDP, ports).
4. Add **Endpoint Groups** per region and configure the traffic dial.
5. Add **Endpoints** (ALB, NLB, EC2, EIP) with optional weights.
6. Configure health checks per endpoint group.

- **Use when you need static IPs** for whitelisting or non-HTTP protocols.

- Endpoints can be ALB, NLB, EC2, or Elastic IP.
