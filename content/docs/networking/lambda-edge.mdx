## Resumen

**CloudFront Functions** y **Lambda@Edge** permiten ejecutar código en las edge locations de CloudFront, lo más cerca posible de tus usuarios. Pueden manipular requests y responses que fluyen a través de CloudFront sin necesidad de un servidor backend.

## Cuándo se Ejecutan

### CloudFront Functions

- Cuando se **recibe un request** del viewer (usuario)
- Antes de **enviar un response** al viewer

### Lambda@Edge

- Cuando se **recibe un request** del viewer
- Cuando CloudFront **envía un request al origin**
- Cuando se **recibe un response del origin**
- Antes de **enviar un response** al viewer

## Comparación

| Característica | CloudFront Functions | Lambda@Edge |
|---|---|---|
| **Duración** | Sub-milisegundos | Milisegundos o más |
| **CPU/Memoria** | Fijos, ligeros | Ajustables |
| **Acceso a red** | No | Sí |
| **Acceso a filesystem** | No | Sí |
| **Librerías externas** | No | Sí (AWS SDK, etc.) |
| **Acceso al body HTTP** | No | Sí |

## Casos de Uso

### CloudFront Functions

- **Normalización de cache keys** — transformar atributos HTTP para mejorar el cache hit ratio
- **Manipulación de headers** — insertar, modificar o eliminar headers HTTP
- **Redirecciones y reescrituras de URL**
- **Autorización de requests** — validar tokens JWT inspeccionando headers de autorización

### Lambda@Edge

- **Funciones de larga duración** (varios milisegundos o más)
- Funciones que necesitan **CPU o memoria ajustable**
- Funciones que dependen de **librerías externas** (AWS SDK, etc.)
- Funciones que necesitan **acceso a red** para servicios externos
- Funciones que necesitan **acceso al filesystem** o al body de requests HTTP

<Callout type="warn">
**Para el examen SAA-C03:** CloudFront Functions son para operaciones ligeras y rápidas (headers, redirects, auth). Lambda@Edge es para funciones más complejas que necesitan red, filesystem o mayor tiempo de ejecución. Ambos ejecutan código en edge locations. Elige según la complejidad de tu caso de uso.
</Callout>
