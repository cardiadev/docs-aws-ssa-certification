## Resumen

**Amazon Route 53** es el servicio DNS completamente administrado de AWS. Ofrece registro de dominios, gestión de registros DNS, health checks y múltiples políticas de enrutamiento para controlar cómo se dirige el tráfico a los recursos de AWS y externos.

Es un **servicio global** (no regional) altamente disponible y escalable que opera con SLA del 100%.

## Conceptos Clave

### Alias vs CNAME

| Feature | Alias | CNAME |
|---|---|---|
| **Zone apex (root domain)** | Sí (`example.com`) | No (solo subdominios) |
| **Recursos de AWS** | Sí (nativo) | No (nombre de host cualquiera) |
| **Cargo por consulta** | Sin cargo adicional | Cargo estándar |
| **Targets válidos** | Solo recursos AWS | Cualquier hostname |
| **TTL** | Gestionado por AWS | Configurable manualmente |
| **Health checks** | Sí (para algunos targets) | Sí |

> **Regla clave:** Usar **Alias** para apuntar a recursos AWS (ELB, CloudFront, S3, API Gateway). Usar **CNAME** para apuntar a hostnames externos. **Solo Alias puede usarse en el zone apex** (dominio raíz).

### 7 Políticas de Enrutamiento

| Política | Caso de Uso | Health Checks |
|---|---|---|
| **Simple** | Un único recurso de destino | No |
| **Weighted** | A/B testing, migración gradual | Sí |
| **Latency** | Enrutar al recurso de menor latencia | Sí |
| **Failover** | DR activo-pasivo | Requerido |
| **Geolocation** | Contenido por país o continente | Sí |
| **Geoproximity** | Enrutar por proximidad geográfica + bias | Sí (requiere Traffic Flow) |
| **Multivalue** | Múltiples IPs saludables (no es ELB) | Sí |

#### Simple
- Devuelve un registro DNS estático.
- Si hay múltiples valores, devuelve todos y el cliente elige aleatoriamente.
- **No soporta health checks.**

#### Weighted
- Asigna pesos a cada registro (0-255).
- `Peso 0` = no se envía tráfico a ese recurso.
- Útil para **A/B testing** y migraciones graduales.

#### Latency
- Enruta al recurso con **menor latencia de red** desde la perspectiva del usuario.
- Requiere registros en múltiples regiones.

#### Failover
- Configuración **Activo-Pasivo**: primario (active) y secundario (passive).
- **Requiere health check** en el recurso primario.
- Si el primario falla, Route 53 enruta automáticamente al secundario.

#### Geolocation
- Enruta basado en la **ubicación geográfica** del usuario (país, continente, o defecto).
- Diferente de Latency: no mide latencia, solo ubicación.
- Útil para restricciones legales, idioma o personalización regional.

#### Geoproximity
- Enruta basado en la ubicación geográfica con posibilidad de ajustar el sesgo (**bias**).
- `bias positivo` = ampliar el área de cobertura de un recurso.
- `bias negativo` = reducir el área de cobertura.
- **Requiere Route 53 Traffic Flow** (herramienta visual de políticas).

#### Multivalue
- Devuelve hasta **8 registros saludables** por consulta.
- No es un sustituto de un load balancer (no hace routing avanzado).
- Cada registro puede tener un health check asociado.

### Health Checks

| Tipo | Descripción |
|---|---|
| **Endpoint** | Monitorea un endpoint HTTP/HTTPS/TCP |
| **Calculated** | Combina resultados de múltiples health checks (AND/OR) |
| **CloudWatch Alarm** | Pasa/falla según el estado de una alarma de CloudWatch |

- Los health checks de Route 53 se ejecutan desde múltiples ubicaciones globales.
- Un endpoint se considera saludable si **>18%** de los health checkers lo ven como saludable.
- Se puede monitorear endpoints **privados** usando CloudWatch Alarm-based health checks.

### Private Hosted Zones

- Una **Private Hosted Zone** solo es accesible desde **VPCs asociadas**.
- El tráfico DNS no sale a internet.
- Soporta **split-horizon DNS**: mismo dominio con diferentes respuestas según si la consulta viene de una VPC privada o del internet público.

### DNSSEC

- **DNSSEC** agrega firmas criptográficas a los registros DNS para prevenir ataques de envenenamiento de caché.
- Route 53 soporta DNSSEC para zonas públicas.

### Resolver Endpoints

| Tipo | Dirección | Caso de Uso |
|---|---|---|
| **Inbound** | On-premises → Route 53 | Resolver DNS de AWS desde la red corporativa |
| **Outbound** | Route 53 → On-premises DNS | Resolver DNS corporativo desde AWS (hybrid DNS) |

## Tipos de Registros DNS

Route 53 soporta todos los tipos de registros DNS estándar:

| Tipo | Descripción | Ejemplo |
|---|---|---|
| **A** | Mapea un hostname a una IPv4 | `app.example.com → 1.2.3.4` |
| **AAAA** | Mapea un hostname a una IPv6 | `app.example.com → 2001:db8::1` |
| **CNAME** | Mapea un hostname a otro hostname | `www.example.com → app.example.com` |
| **Alias** | Mapea a recursos AWS (extensión de Route 53) | `example.com → xyz.elb.amazonaws.com` |
| **MX** | Mail exchange records | Servidor de correo |
| **TXT** | Registros de texto | Verificación de dominio, SPF |
| **NS** | Name server records | Delegación de zona |
| **SOA** | Start of Authority | Información de la zona |

## Hosted Zones

### Hosted Zone Pública

- Resuelve consultas DNS desde **internet público**.
- Usada para dominios accesibles públicamente.
- AWS cobra por el número de hosted zones y consultas DNS.

### Hosted Zone Privada

- Solo resuelve consultas desde **VPCs asociadas**.
- Múltiples VPCs pueden asociarse a la misma hosted zone privada (incluso entre cuentas con Resource Access Manager).
- Requiere que las opciones de VPC `enableDnsHostnames` y `enableDnsSupport` estén habilitadas.

## Casos de Uso por Política

| Escenario | Política Recomendada |
|---|---|
| Sitio web simple, un servidor | Simple |
| Desplegar nueva versión gradualmente | Weighted |
| Usuarios globales, menor latencia posible | Latency |
| Recuperación ante desastres activo-pasivo | Failover |
| Contenido diferente por país/idioma | Geolocation |
| Expandir/reducir área de cobertura regional | Geoproximity |
| Respuestas DNS con múltiples IPs saludables | Multivalue |

## Configuración

Pasos para crear una política de Failover:

1. Crear una **Hosted Zone** para el dominio.
2. Crear un **Health Check** para el recurso primario.
3. Crear un registro DNS con política **Failover** → tipo **Primary**, asociar el health check.
4. Crear otro registro DNS con política **Failover** → tipo **Secondary** (sin health check requerido).
5. Route 53 enrutará automáticamente al secundario si el primario falla.

<Callout type="warn">
**Exam Tips — SAA-C03:**
- **Alias en el zone apex** (dominio raíz como `example.com`): solo Alias funciona, no CNAME.
- **Geoproximity requiere Traffic Flow** para configurar el bias visual.
- **Failover requiere health checks** en el recurso primario.
- **Weighted con valor 0** = no se envía tráfico a ese recurso.
- **Multivalue NO es un load balancer** — simplemente devuelve múltiples IPs saludables.
- **Latency vs Geolocation:** Latency enruta al de menor latencia; Geolocation enruta por ubicación geográfica.
- **Private Hosted Zones** requieren asociación con una VPC.
- **Health checks de endpoints privados** requieren CloudWatch Alarm-based health checks.
- **Split-horizon DNS:** misma zona, respuestas diferentes para VPC vs internet.
- Route 53 es un **servicio global** — no está en ninguna región específica.
</Callout>
